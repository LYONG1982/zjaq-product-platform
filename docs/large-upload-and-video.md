# 500 MiB 文件与视频链路

2026-10-29；本说明针对本轮源码。真实 CloudBase/网关和微信真机未在本机接入。

## 文件与资源边界

- 单文件 1—524,288,000 字节（500 MiB），PDF、PNG/JPEG/WebP、DOCX/PPTX、MP4/MOV/WebM 一致。501 MiB 的 JSON 上传意图在契约校验阶段拒绝，不写磁盘；绕过意图或字节超过声明也会拒绝。
- 浏览器直接发送 File，服务端按块写磁盘并检查声明长度；不把 500 MiB 聚合成 Buffer。进程 Mock 会话/Cloud 当日上传预算为 4 GiB、500 个任务，派生安全预览也计入预算。Mock 同时最多 2 个字节流/2 个解析；Cloud 最多 4 个上传/2 个解析。
- 单次接收最长 15 分钟、30 秒无字节终止。解析最长 120 秒，在独立 Node 子进程中限制 V8 heap 为 384 MiB。超时、拒绝、断流均清理半文件；不可原位覆盖 READY。Cloud 写租约 40 分钟覆盖接收、对象传输、解析的最坏时长，最终提交检查 lease ID 防旧处理覆盖。
- PDF 用文件范围传输读取，初始 64 KiB，不整件读取；页数最多 200、总操作符最多 100 万、解析累计读取最多 128 MiB，拒绝脚本及附件。500 MiB 是上传字节上限，不承诺接受超出复杂度预算的文档。
- Office 用随机访问 ZIP 和逐条目流式校验，源文件只存储、不转换。总解压最多 600 MiB、XML 总量最多 20 MiB、条目最多 2,000，拒绝 ZIP 炸弹、宏/活动对象、外部引用和不完整 CRC。
- 图片最多 2,000 万像素、单帧；原始字节及校验值保留，安全 PNG 派生件（最大 80 MiB）用于浏览。源件下载/图集 ZIP 使用原图，公开媒体不直接返回未经清理的源图。存储元数据不持久化本机路径。

## 视频与运行依赖

服务端必须安装受信任的 FFmpeg `ffprobe`；可通过 `FFPROBE_PATH` 指定绝对路径，不允许相对路径。没有工具、工具超时或编码不符时检查拒绝并清理，禁止绕过检查接受视频。验证环境另外需要 `ffmpeg`，测试动态生成 1 秒蓝色视频，不提交视频二进制或真实产品资料。

MP4/MOV 使用 H.264，音频 AAC/MP3；WebM 使用 VP8/VP9，音频 Opus/Vorbis。最多一条视频和一条音频，最长 4 小时、最高 3840×2160、4:2:0；拒绝其他轨道及附件。ffprobe 仅允许 file 协议，MOV 禁止外部 dref 与绝对路径；系统不转码。播放器提供终端不兼容提示，建议 MP4，MOV/WebM 不能据 H5 测试推断为所有微信设备可播放。

统一上传入口自动识别预览/图片序列/视频/源文件，仍由管理员选择资料用途。小程序/H5 仅已发布宣传资料；销售仅当前已发布版本；管理端可预览历史。视频与 PDF 通过当前版本资源路径请求 Range，身份、用途、当前发布及撤回条件每次重新核实。已传给浏览器的缓存字节无法召回；播放器在播放/回到页面及周期复核时停止失效资源。

## 后台媒体会话

`POST /api/v1/admin/media-session` 只接受已有 Bearer，返回 204 及 5 分钟 HttpOnly、SameSite=Strict、生产 Secure 的路径受限 Cookie。Cookie 用 AES-256-GCM 加密，服务端校验到期，禁止明文令牌/URL 令牌；仅后台资产 GET 接受 Cookie，不用于其他管理接口及写操作。每个请求仍重新验证角色和禁用状态。

生产需 `ADMIN_MEDIA_SESSION_SECRET` 为独立 32 字节 Base64 密钥，多实例共享；缺失时媒体会话拒绝。后台和 API 必须同站或反向代理；不放宽为第三方跨站 Cookie。播放器每 4 分钟续期而不修改视频 src，卸载停止续期；身份失效即停止播放。仅精确允许的 Origin 返回 CORS credentials。

## Cloud 私有流、Range 缓存与恢复

使用官方 SDK 获取对象上传授权/临时地址，实际 COS 字节通过 HTTPS pipeline 传输、等待落盘完成。不用 SDK 3.18.7 的 `downloadFile(tempFilePath)`，其本机源码在文件 writer 完成前就返回。对象 URL 只在服务器内部使用，HTTPS/443、COS/CloudBase 域名白名单、无跳转；15 分钟总时长和 30 秒空闲，长度与校验失败即清理。拒绝对象不留下已删除 fileId，派生上传失败或提交失败清理新对象。

Range 首读对象在受限 0700 临时目录校验大小和 SHA-256，随后按不可变对象 ID/校验/原件或派生件复用。缓存最多 2 GiB、最多 4 个并发对象读取、同对象并发去重、引用计数，空闲 2 分钟过期，磁盘不足拒绝。命中仍重新核实数据库元数据及当前 HTTP 权限并 stat 大小。进程正常退出/信号清理缓存。响应 30 秒空闲/15 分钟绝对时限；中断销毁流并释放引用。首次源对象读取及 SDK 授权仍须实际云环境核实。

销售下载用浏览器下载器流式接收，图集为逐张原图 ZIP64 流（按页码命名，不暴露内部编码），完整成功响应计一次下载。备份/恢复按块算 SHA-256/上传，包含 fileId 与 previewFileId 两份对象并验证映射，不把大文件读入 Buffer。

## 本地证据

`node --import tsx --test tests/unit/upload-video.test.ts tests/unit/workflow.test.ts`：此前 12/12 通过；随后 `upload-video.test.ts` 增补 500 MiB MP4 后 7/7 通过。独立临时 HTTP 服务真实传输 499 MiB（523,239,424 字节）和 500 MiB（524,288,000 字节），检查 READY、校验值、206 Range 和 CloudAssets 磁盘替身读取通过；501 MiB 在上传意图阶段拒绝。该次父进程 RSS 快照分别为 158/186 MiB（非完整峰值测量），含检查/对象替身读取分别 3,192/2,997 ms。本地磁盘/回环网络性能不能推断为公网性能。

另对合法 free box 填充的 500 MiB MP4 完成实际流式写入、ffprobe 和全文件校验，通过。已覆盖三类视频及伪装视频拒绝、原图/派生隔离、后台 Cookie 只读/篡改/到期/账号禁用、公开视频下架、图集 ZIP 外部 unzip 校验、缓存去重/TTL、Cloud 拒绝文件删除及元数据清理。Playwright 场景位于 `tests/browser/upload-video.spec.ts`；最终全量结果由本轮总验证报告记录，不在此将未执行的真机/云测试冒充通过。

补充浏览器证据：`upload-video.spec.ts` 两个场景已分别定向通过：统一入口 MP4 上传、后台 HttpOnly 媒体预览、发布后 H5/销售视频及销售下载；真实浏览器 500 MiB File 上传 READY 和 501 MiB 本地拒绝。另强制保留原生 fetch、移除测试夹具的无关 CDP 网络拦截后，同一 500 MiB 场景也通过（2.7 秒）；此前 Chrome 崩溃来自自动化拦截大 postData。最终用例对大文件关闭无关路由拦截，实际访问配置 API；应用默认使用原生 XHR File 上传并显示百分比/已传 MiB，不生成 JavaScript 大字符串。完整回归以总报告为准。
