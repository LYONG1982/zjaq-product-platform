# 编码、型号和公开标识索引核验

2026-10-29。此工具不重新编码 27 款旧产品，不猜测型号、类型或属性，不修改草稿和不可变发布快照。

## 修复的缺口

旧环境若有五段编码而无 `control/code-ZJ-…`，新建原先从 001 开始：已有 001 会反复冲突且事务回滚，不能新建；只有 005 时会错误分配空洞 001。计数器核验据所有现存主档的内部编码高位计算，下一号只升不降，999 用尽后保持 1000 并拒绝新分配。

原型号唯一性只依赖 `control/model-<规范化型号摘要>`；历史环境缺索引时，新产品可能复用另一产品或旧发布快照的型号。核验包含全部当前草稿、全部发布快照及既有保留型号索引（即使该旧拼写不再出现在当前草稿）。型号采用现行 NFKC、去首尾空白及大小写归一化；跨产品冲突拒绝执行，不能靠覆盖索引选择归属。软移除的主档也保留身份、型号和流水占用。

同时验证已有 UUID 与公开映射一一对应，补缺失加速索引；不会给没有 UUID 的产品自动分配公开标识，后者使用独立 UUID 迁移工具。孤立索引、错误计数器、冲突映射或孤立草稿/发布记录均需人工核对后再运行。

## 启动检查与离线审阅

正式 API 在监听端口前只读核验上述索引。有缺失或落后则拒绝启动并给出本工具路径，不在启动时写库；全新初始化的 27 款旧编码、空型号产品可以通过，不补虚构内容。正式升级应先停止旧版写入者并生成私有备份，完成维护操作后再启动新版；运行期间不能绕过应用直接改型号/编码/索引。

无参数仅显示用法，不连接云：

```sh
node --import tsx scripts/reconcile-product-indexes.ts
```

基于私有完整备份生成计划，仍不连接云：

```sh
node --import tsx scripts/reconcile-product-indexes.ts --file /private/product-backup.json --out /private/product-index-plan.json
```

计划包含修订号、全清单指纹、每项索引的前后值及计数；保留原计数高水位和旧型号占用。输出文件为 0600，标准输出只包含数量摘要，不打印私有计划。私有备份/计划包含内部产品标识，不提交到公开源码仓库。

## 显式维护操作（本轮未执行真实云）

只有获得具体真实环境操作授权、核对备份和恢复方案后，操作员才能运行：

```sh
node --import tsx scripts/reconcile-product-indexes.ts --file /private/product-backup.json --plan /private/product-index-plan.json --environment exact-environment-id --apply
```

环境须同时匹配备份和 `CLOUDBASE_ENV_ID`。工具先验证全部私有备份对象的文件安全、完整字节和 SHA-256，再检查审阅计划与备份一致、当前修订号，取得维护所有权，重新核对产品/草稿/全部发布及旧索引指纹，事务内只补索引或抬高计数器，并写审计及新修订号。成功或失败只释放自己取得的维护标记；不会删索引、覆盖冲突归属、修改产品记录或接入 Mock 回退。真实 CloudBase 事务容量、写入权限和运营维护窗口需独立验证。
