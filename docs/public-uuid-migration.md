# 公开 UUID 迁移与旧链接处理

公开产品地址使用独立随机 UUID v4。内部 `ZJ-*` 编码只在管理和私有存储中使用。公开详情、预览、图片、搜索和资料目录不接受内部编码；旧的含内部编码的直达地址返回不存在，不提供可枚举的“旧编码查新 UUID”公开接口。PC 旧页面路径保留，但须先登录，产品参数也须使用 UUID。

既有缺少 UUID 的已发布产品在迁移前保持隐藏，不能通过一次普通读取静默改写数据。迁移只新增主档 `publicId` 和私有 `control/public-UUID` 索引，不改变内部编码、草稿、历史版本、发布内容或资料分类。27 款旧产品的五段编码迁移仍按用户要求等待属性和型号确认。

## 工具与步骤

以下命令是运维说明。本轮只在隔离事务替身中执行迁移测试，没有连接或改写真实云。

1. 对确定的目标环境执行现有私有完整备份，保留原始 JSON 和 `.assets` 对象目录，核对环境和修订号。备份及迁移计划含私有映射，应存放在受限的仓库外目录或被忽略的 `work/`，不可提交 GitHub。
2. 离线生成候选映射，不连接云：

   ```sh
   node --import tsx scripts/public-id-migration.ts --backup /private/path/backup.json --output /private/path/public-id-plan.json
   ```

3. 审核全部映射、重复标识、备份和数据完整性。原有 UUID 保持不变；新 UUID 在计划写入后固定，重新生成另一份计划会产生不同候选，不能混用。
4. 获得具体环境的迁移授权后才执行：

   ```sh
   node --import tsx scripts/cloud-operations.ts migrate-public-ids --apply --environment EXACT_ENV --backup /private/path/backup.json --file /private/path/public-id-plan.json
   ```

   环境必须匹配 `CLOUDBASE_ENV_ID` 和备份。工具检查备份修订号、现有主档指纹和完整清单，取得维护标记后原子提交映射和审计。并发改动、重复 UUID、索引冲突或修改计划均会拒绝；结束后只释放自己取得的维护标记。请求写入在维护期间由现有修订号控制拒绝。
5. 对迁移后的公开目录、详情、宣传/技术分类、预览、媒体、下架和销售权限分别检查，更新微信中分享的正式 UUID 链接。不要把旧内部编码重定向能力重新加入公开接口。
6. 再次备份，在独立空目标恢复并核对 UUID 和对象校验和。原始备份提供回退来源；现有恢复命令只允许不同且为空的隔离目标，禁止覆盖生产。真实环境失败后应保持维护并由操作员审核，不凭本地测试宣称恢复完成。

隔离测试覆盖 27 款产品、映射唯一性、原编码和草稿保持、失败回滚、重新预检后重复执行、备份 JSON 往返、无效及重复 UUID、计划过期和索引冲突。真实数据库事务限制、执行窗口、真实对象恢复及微信旧分享链接需在目标环境独立验收。
