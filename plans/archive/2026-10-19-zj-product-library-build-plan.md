## 4. 产品与技术基线

前台流程：找产品 → 理解产品 → 当前资料 → 预览。

后台流程：按分类模板新建 → 制作 → 预览 → 发布 → 更新／下架。

| 层 | 计划采用 | 实现重点 |
| --- | --- | --- |
| 微信小程序／移动 H5 | Uni-App + Vue 3 + TypeScript | 共用业务页，预览与生命周期分别适配 |
| PC 门户 | Next.js + TypeScript | 只读当前发布 DTO，显式内容缓存策略 |
| PC 后台 | Vue 3 + TypeScript | 分类模板驱动编辑，真实身份接入单独验证 |
| 统一 API | Node.js + TypeScript 模块化单体 | 身份、发布状态、版本、资源归属均在服务端判断 |
| 正式数据与文件 | CloudBase 文档数据库、私有存储 | 与 Mock 使用同一契约；禁止生产回退 Mock |
| 共享部分 | DTO、校验、模板、Token、API 客户端 | React／Vue 视图分别实现，不强行共享组件 |

保留 `DRAFT / PUBLISHED / OFFLINE` 三种业务状态。草稿与不可变发布快照分开，`draftVersion` 与 `publicationVersion` 分开；资料版本和资源引用固定，不以最后上传文件替代当前发布内容。

不迁入 V3 的客户端角色切换、localStorage 业务库、双审、资料授权、下载原件、派单、个人中心与回滚流程。V3 的 `shared/store.js` 已实际读到这些旧机制；其 `miniapp` 是 HTML 原型，`package.json` 仅有 `node server.mjs` 启动脚本。

## 6. 真实接入前的关键风险

### 6.1 CloudBase 事务与资产规模

本次已查阅 CloudBase 官方事务文档：服务端事务存在单次最多 100 次操作、30 秒、使用 doc 而非 where 等约束。官方文档能力不等于当前账户已验证可用。[官方事务文档](https://docs.cloudbase.net/en/database/transaction)

包内允许每产品 20 份材料、每材料 200 张图片，理论上达到 4000 个预览资产引用。因此不能在一次发布事务中逐个读取全部资产文档。建议接入真实库前验证：不可变 READY 资产的批量预检／完整性摘要，以及小范围的草稿版本、发布指针、release、幂等与审计事务；禁止原位变更或删除被引用资产，避免预检后条件改变。实际集合大小、单文档限额、事务重试和跨实例竞争须做真实 PoC 后定稿。

### 6.2 两类文件预览与缓存

Uni-App 官方表格标明 `uni.openDocument` 不支持 H5，微信端需要本地文件路径；H5 采用网页查看器，小程序采用临时文件与原生预览，分别验证。[Uni-App 文件 API](https://uniapp.dcloud.net.cn/api/file/file)

Next.js 官方说明 `fetch` 的 `no-store` 行为。门户仍需在生产构建下核查路由缓存、客户端恢复、资源代理与发布状态，不能只设置一处 fetch 就宣称下架失效。[Next.js fetch](https://nextjs.org/docs/app/api-reference/functions/fetch)

公开资源每次检查当前 release／材料版本，支持正确的 Range 与 200／206／416；后台资源必须保持认证。预览代理不得提供永久对象直链。已传输到设备的内容无法追回。
