## 调查所得与方案

1. 当前已支持 MP4/MOV H.264 + AAC/MP3（或无音轨）、WebM VP8/VP9 + Opus/Vorbis，单文件 ≤500 MiB；保留这些规则、权限、上传优先流程、暂存替换与 V01.0，不放宽安全校验。
2. API 客户端遇到 HTML/空响应时会直接 JSON 解析或访问 null，导致 HTTP 413/502/503 等原因被异常覆盖。为非标准响应增加安全兜底与稳定错误码；保留已有标准 JSON 业务错误和字段错误，提取可用 requestId，避免输出服务器 HTML/路径。
3. 上传失败后的状态回查若再次失败会覆盖首次原因。保留首次错误；按阶段生成可复制问题详情，含错误码、原因、建议和请求编号（存在时），不改服务端响应字段。网关 413 要明确可能低于应用 500 MiB 限制，不能谎称用户文件必然超限。
4. 视频解析补齐：ffprobe 启动/配置/异常结果与损坏区分；先检查编码再检查像素/尺寸，避免 H.265 10bit 被误报为尺寸限制；分别说明视频或音频编码，保留轨道/尺寸/时长限制。原始 stderr 和本机路径不返回给用户。
5. 前端选择错误继续就地显示；上传运行错误显示“具体原因 + 下一步 + 问题详情”，失败仍可重试/重选，READY 后可“检查预览件”。不增加业务字段，不变更已发布数据。
